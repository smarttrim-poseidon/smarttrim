Technical notes

Pipeline. OpenCV ArUco, dictionary DICT_4X4_50, marker ID 0, sub-pixel corner refinement, run offline on every frame of the upright video (vision/aruco_check.py --scan). The page shows only what the detection CSV records; frames are matched to video time with the MP4's own presentation timestamps.

Overlay. Corners are numbered in the marker's own order (0 top-left, clockwise) and drawn only on frames where the CSV records a detection. A dashed red outline marks a detection inside a manually annotated invalid segment.

Statistics. Counted in the browser from each recording's detection CSV. Rates depend on camera viewpoint, distance, lighting and motion, so they are not a like-for-like comparison and not a measure of vessel stability.

Shows marker detection and corners only — no pose, roll, pitch or stability is derived from the video.

How the numbers are produced

  1. RecordVideo of the V5 prototype carrying a 40 mm ArUco marker on its deck.
  2. DetectOpenCV ArUco (DICT_4X4_50) searches every frame for marker ID 0.
  3. LogEach frame's result and the marker's four corners are written to a CSV.
  4. CountDetection rate = frames with ID 0 detected ÷ frames analysed.

Detection rates reflect different camera viewpoints and recording conditions; they are not direct measures of vessel stability.

Technical notes

ArUco finds marker ID 0 (DICT_4X4_50) and its four corners in each frame; it does not measure roll, pitch, stability or recovery. The recordings use different camera positions (bench: moving camera, low fixed camera; water tank: handheld, approximately stationary camera from above), so their rates are not a like-for-like comparison. For the fixed-camera bench recording, frames 769–909 are excluded from the valid-frames rate because the marker card had fallen off.
